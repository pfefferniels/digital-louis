# Digital Louis renderer

Draws the préludes non mesurés from their MEI encoding anywhere on the
continuum between the editors' measured reading (`t = 0`) and the reading
order of the source (`t = 1`).

```ts
import { prepare, render } from './renderer'

const score = prepare(meiDocument) // everything that does not depend on t
element.innerHTML = render(score, t)
```

Try it at `/<work>/renderer`, e.g. `/digital-louis/prelude10/renderer`.

## How it works

Each stage is a pure function of the one before; nothing is mutated.

| module | does |
| --- | --- |
| `mei.ts` | reads the dialect into the immutable model of `model.ts`; the only module that touches the DOM |
| `time.ts`, `reading.ts` | notated onsets (exact, `Rational`) and the reading order that `@precedes` describes |
| `analysis.ts` | every head with its staff position, glyph, onset, reading step and stem direction |
| `horizontal.ts`, `spacing.ts` | gives every head two places: one by notated time, one by reading order |
| `staff.ts`, `controls.ts`, `page.ts` | engraves a point of the continuum: `x = lerp(measured, reading, t)` |
| `svg.ts` | writes the page as SVG |

Both layouts space by the same rule: a gap is never smaller than what the
notation needs (`noteheads.ts` computes it with the same functions that later
draw), and otherwise proportional to notated time or to one reading step. The
stretch that fills a system is solved exactly. What the source does not read
(rests, say) and what is placed by time stamp (figured bass, cadence labels)
follows a piecewise linear map from notated time to x, built from the notes it
does read.

All layout is in staff spaces, y down. Glyphs come from Leipzig (SIL OFL);
`leipzig.ts` is generated by `tools/renderer/extract_glyphs.py`.

## The SVG

The output keeps the class and data vocabulary the viewer selects by, so
`changeVisibilities`, `insertShadowSemibreves`, the tenue engine and the
facsimile linking work on it unchanged:

`.system > .measure > .staff > .layer.<voice> > .note.<type>` with
`.notehead`, `.stem`, `.accid`, `.dots`, `.flag`; `.beam polygon`,
`.ledgerLines`, `.tie`, `.trill`, `.mordent`, `.harm .fb`, `.dir`,
`.bracketSpan`, `.barLine`, `.clef`, `.pgHead`; `data-id`, `data-corresp`,
`data-precedes`, `data-next`. Glyphs are `<use xlink:href>` elements with
`x`, `y`, `width` and `height`.

## The dialect

Supported: two or more staves with C, F or G clefs; layers as voices; notes
(breve to eighth, dots, written accidentals, grace notes as ornaments, cue
size), chords, rests, spaces, beams, grace groups; ties, trills, mordents,
figured bass (`harm/fb/f`), directions and bracket spans by time stamp;
encoded system breaks. `annot` is ignored.

Anything else is reported as `UnsupportedMei`, naming the element, rather
than drawn wrong. Not yet supported: key signatures, clef changes, slurs,
fermatas, turns, tuplets, sixteenths.
